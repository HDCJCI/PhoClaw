# v1.12.0 — 改一行只发一行

> 发布日期：2026-11-27 · versionCode 24 · 需要 Android 8.0（API 26）以上

## 一句话

新增 `edit` 指令：改几行就只发那几行，不再把整个文件重发一遍。顺带把「改了哪儿」
变成看得见的红绿对比，并且能一键撤销。

## 之前是什么样

提示词里写的是「改代码优先用 `write` 重写整个文件」。这句话在聊天框里没问题，
放到手机上就有两个后果：

**第一，贵。** 改一个 200 KB 的文件里的一行，模型要把 200 KB 原样吐一遍。
按 4 字符 ≈ 1 token 算，五万 token，几次编辑就把上下文窗口挤爆了。

**第二，危险。** `write` 是覆盖写，没有备份。模型哪次漏了一行、或者把
「此处省略」这种占位符真写进文件，原内容就没了 —— 手机上还没有 git 可以救。

这两件事叠在一起，让「AI 帮你改代码」这个功能在最关键的地方不可靠。

## 现在：`edit`

````
```phoclaw:edit src/Greeter.kt
--- 查找
fun greet() {
    println("hi")
}
--- 替换
fun greet(name: String = "世界") {
    println("hi, $name")
}
```
````

只发这 8 行，不再发整个文件。

### 唯一匹配是硬约束

这是整个功能里最重要的一条设计：**「查找」必须在文件里只出现一次**。

不这么要求会怎样？模型想改 `    }`，而这个片段在任何 Kotlin 文件里都有几十处。
按「第一处匹配」去替换，会得到一种最难排查的失败 —— **日志说改好了、界面上一切正常、
改的却是别的地方**。用户要等到运行报错，甚至上线之后才发现。

所以：

| 匹配情况 | 行为 |
|---|---|
| 1 处 | 替换，回执里带上改动前后的上下文 |
| 0 处 | 拒绝，提示先 `read` 确认内容 |
| 多处 | 拒绝，并列出「出现了 3 处，在第 12、47、103 行附近」 |

被拒绝时模型会收到具体的行号，加一行上下文重试即可。多花一轮，换「绝不会改错」。

### 缩进容错

模型抄代码经常丢缩进。精确匹配失败后会再试一次「忽略每行首尾空白」的整块匹配，
命中后按**文件里的真实缩进**重排替换内容。

两种写法都能成功：

````
--- 查找
fun greet() {          ← 顶格写的，文件里其实是 4 空格缩进
    println("hi")
}
````

替换内容本身带缩进时也不会双重缩进 —— 先去公共缩进，再补文件里的实际缩进。

## 改了哪儿，看得见

每轮结束，AI 气泡下方多一张卡片：

- **汇总**：`修改 2 个文件 +7 −3`
- **逐文件**：`M src/Greeter.kt` / `A README.md`，下面是对应的行级 diff
- **红绿标注**：删除行红底 `−`，新增行绿底 `+`，未变的行灰字作上下文
- **上下文裁剪**：只显示每处改动前后各两行，中间隔得远的地方折成「… 省略 42 行 …」

长文件不会把聊天刷屏：单个文件最多显示 120 行 diff，超过 2000 行的文件直接
退化成「整体替换」，并明确说明「文件太大，不逐行比对」。

## 撤销

卡片右上角有「撤销」。点下去弹一次确认，列出会动的文件：

```
删除 src/Greeter.kt      ← 新建的文件，撤销 = 删掉
还原 README.md           ← 改过的文件，撤销 = 写回原内容
恢复 notes.md            ← 删掉的文件，撤销 = 恢复
```

三个实现上的取舍：

**倒序回放。** 同一个文件在一轮里被改了三次，只有从后往前才能逐步退回最初状态。
正序的话第二次「恢复」会把第三次的结果又覆盖回去。

**备份存在会话里，不是另一个目录。** 变更记录（改动前后各一份内容）挂在消息上，
跟着会话 JSON 落盘。好处是撤销天然按轮次分组 —— 用户看到「这条回复改了 3 个文件」，
想撤的就是这一批；换成全局的备份目录，还得额外维护「哪几条属于哪轮」的对应关系。

**超过 512 KB 就老实说不能撤。** 大文件不存正文，卡片上直接写「文件过大，只记录了路径」。
比假装能撤销、点了却没反应强。

## 其他四件

### 代码块语法高亮

之前代码块只有等宽字体和深色底。现在按词法着色：关键字、字符串、注释、数字、类型
各一色，深色浅色两套配色分别调过。

覆盖 20 多种语言（Kotlin / Java / Python / JS / TS / Go / Rust / C / C++ / C# / Ruby /
PHP / Swift / Lua / Dart / Shell / SQL / JSON / YAML / HTML / CSS / Gradle），
别名也认（`kt`、`py`、`c++`、`sh`、`yml` 都行）。零新增依赖，手写扫描器两百行。

只做词法不做语法分析，所以：

- 字符串里的 `if` 不会被当成关键字（扫描到引号就整段吃掉）
- 未闭合的引号只吃到行尾，不会把后面整个文件染成一种颜色（流式输出时经常出现）
- 美化不了「宏里的关键字」这种需要语义的场景 —— 但那本来也不是读代码时的痛点

### 上下文占用条

输入框上方常驻一条 2dp 的进度条，显示当前估算占用与预算的比例。三档配色：
绿色照常聊、黄色（60%）该考虑收尾、红色（85%）要么压缩要么开新会话。

之前这个数字藏在「更多」菜单里，关掉自动压缩的用户看到的永远是 0。现在每轮结束算一次。

点一下不会直接压缩 —— 压缩要额外调一次模型（花钱、耗时），误触的代价不该由用户承担，
所以点开是一个小菜单。同理，之前从菜单里误点一下就压了。

### 导出对话

「更多」→「导出对话」，存成 Markdown。用系统文件选择器挑位置，不写进工作区 ——
导出文件通常是要发出去的，放工作区里反而会让 AI 下次 `tree` 时把它当成项目文件。

工具日志收在 `<details>` 里，改动文件列成清单。不导出内部回灌消息（工具结果原文、
附件正文）—— 那些是给模型看的中间产物，掺进去会让导出的文件没法读。

## 升级注意

- **没有破坏性变更。** 旧会话照常打开，历史消息没有变更记录，只是不显示卡片。
- 提示词自动更新：`write` 的规则从「优先重写整个文件」改成了「小改用 `edit`」，
  工具段每次请求现拼，不需要你手动改什么。
- 旧前缀 `espclaw:` 与 `edit` 的别名（`patch` / `replace` / `sub`）都可正常使用。

## 已知限制

- **目录删除不备份**。`delete 某个目录` 只记路径不记内容 —— 递归备份一整棵树
  在手机上可能几百 MB，代价不成比例。这类操作仍然走确认框。
- **`copy` / `move` 不进变更记录**。它们产出的文件没有 before/after 对照，
  放进卡片会让人误以为能撤销重命名。
- **自动化的后台任务不记录变更**。无人值守场景没人点撤销，记录只是白占空间。
