**长期记忆 + 上下文压缩。** 这一版解决两件事：AI 记不住东西，和聊久了会崩。前者是体验问题，后者是会让对话彻底不可用的硬故障。

---

## 🧠 长期记忆：`MEMORY.md`

新增 `memory` 指令，配一份跨会话的 `MEMORY.md`。它存在 **App 私有目录**（`files/MEMORY.md`），**每一轮都注入系统提示词**。

### 为什么不放工作区

工作区是 SAF 目录，你随时能换；没授权工作区时更是根本没有记忆。把记忆绑在一个可变的东西上，等于没有长期记忆。

放在私有目录的代价是没法用自己的文件管理器直接改 —— 所以设置页做了一份完整编辑器，等宽字体，改完即生效。

### 谁会往里写

AI 和你都能写。提示词里给它划了一条线：

> **这条信息下个月还成立吗？不成立就别记。**

符合的例子是偏好、项目约定、长期有效的背景；不符合的是「今天下午三点提醒我」这种一次性信息 —— 那种应该走定时任务，不是记忆。

它写完必须告诉你「记了什么」。记忆是隐形的，不说你不知道它往里塞了东西。

### 怎么用

```
memory AI 回答默认用简体中文，技术问题给代码不要给长段落
memory forget 中文          ← 按关键词删除
memory                      ← 不带参数，列出全部
```

写入前会去重（忽略大小写）。上限 200 条 / 20000 字符，注入时超 8000 字符截断 —— 记忆不能成为撑爆上下文的原因，那恰好是它本该缓解的问题。

格式很宽松，只有 `- ` 或 `* ` 开头算一条，日期前缀可选：

```markdown
# 长期记忆

- [2026-11-01] 用户偏好中文极简交流，不喜欢长篇解释
- [2026-11-01] 项目用 Kotlin 2.0 + Compose，不要建议降级到 1.x
- 手写的条目不带日期也认
```

## 📦 上下文压缩：滚动摘要

在这之前，`buildApiMessages()` 是**无条件全量发送**，一条历史都不丢。工具结果回灌尤其能撑 —— 一次 `read` 一个几千行的日志，就是**几万 token 常驻上下文**。聊到几十轮，请求迟早撞上后端长度上限，而报错信息通常难以理解。

现在超预算时，把最老的一批对话调模型压成摘要，与上一份**增量合并**。

| 设计 | 为什么 |
|---|---|
| **界面一条不丢** | 摘要只是「发给模型的版本」，往上翻还是全文。删用户消息比超限严重得多 |
| **按 user 边界切分** | 切出去那段必须以 assistant 结尾，否则会留下「没有提问的回答」 |
| **末尾保留 6 条原文** | 最近聊的必须是原话，摘要会丢细节（可调） |
| **增量合并** | 旧摘要 + 新批次 → 一份新摘要，不会摘要套摘要逐层衰减 |
| **摘要落盘** | 会话 JSON 存 `summary` + `summarizedCount`，重开应用不失忆 |

预算按字符估算（不用 tokenizer —— Android 上塞一份词表要几 MB，为估算不值得）：CJK 1 字 ≈ 1 token，其余 4 字符 ≈ 1 token，误差 ±30%。默认 **32000**，设置页可调。

**触发方式**：每轮前自动（可关），或聊天页顶栏「更多」→「压缩上下文」强制压到六成。菜单里顺带显示当前估算占用。

**两道兜底**：压缩失败（网络 / 模型抽风）降级成「丢弃最早的几条」并在界面告知，不让对话卡死；单条超预算 35% 就地截断 —— **只削发给模型的那份副本，界面仍是全文**。

## 🐛 修掉的两个真 bug

**压缩点从不前进。** `alignToUserBoundary` 里写了「`candidate >= limit` 就直接返回」，而 candidate 恒等于 `maxCut` —— 这个短路把整个函数变成空操作，切分点永远落在 assistant 上。改成从 `maxCut` **往回**找最近的 user。

**消息被双重跳过。** `contextMessages()` 调 `buildApiMessages()`，后者已经跳过了被摘要覆盖的部分，压缩器又 `drop(summarizedCount)` 一次。结果是压缩点一路往后窜、切分下标和发送下标彻底对不上。拆成两个参数解决。

两个都是写 Python 复刻跑测试时才暴露的，光看代码不容易发现。

## 📥 安装

下载下面的 **`app-debug.apk`**，直接覆盖安装。

`versionCode` 从 17 升到 18，**可以直接覆盖，不需要卸载旧版**。如果系统提示「应用未安装」，多半是之前装过不同签名的构建，卸载后重装即可（会话数据会丢，可以先在设置里把 `MEMORY.md` 内容拷出来）。

首次运行没有 API Key 的话对不了话 —— 见 [配置 API](https://github.com/HDCJCI/PhoClaw#配置-api)。

## ⚠️ 已知限制

- **`run` 不支持二进制文件** —— Android 10+ 的 W^X 策略禁止执行可写目录里的 ELF，这是 SELinux 层面的拦截，不是权限问题。`.py` / `.js` / `.cpp` 这类走 Wandbox 远程执行，**代码会发送到 wandbox.org**，且默认关闭。
- **token 估算是近似值** —— 误差 ±30%。如果后端仍报超限，把「上下文预算」调小一档。
- **压缩会损失细节** —— 摘要是有损的。需要精确保留的内容，让它写进 `MEMORY.md` 或落成工作区里的文件。
- **1.6.4 之前没有 git 记录** —— `CHANGELOG.md` 里那些版本没有确切日期。
