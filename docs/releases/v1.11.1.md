**自定义提示词不再覆盖工具说明。** 上一版有个设计缺陷：只要点过一次保存，整份提示词就被固定成字符串，之后新加的工具、改过的开关说明全都进不来 —— 模型不知道有 `shell`，用户也不知道自己那份已经过期了。

---

## 问题出在哪

1.11.0 之前的实现：

```
用户点保存
   ↓
prefs["system_prompt"] = 完整的提示词（开场白 + 工具清单 + 示例 + 规则）
   ↓
之后每次取 systemPrompt，直接返回这个字符串
   ↓
工具表更新 → 没有任何效果
```

后果不是「少了一条说明」，而是**模型彻底不知道某些指令存在**。1.10.0 加了 `shell`，自定义过提示词的用户在那一版里根本用不上 —— 模型看不见这个指令，自然不会发。

而用户想改的往往只是「回答用中文」「别写注释」这一两句。

---

## 现在怎么工作

拆成两段，各管各的：

```
最终提示词 = 你的部分  +  工具段（每次现拼）
              ↑            ↑
        角色、语气、约定   指令格式 / 示例 / 说明表 / 规则
```

- **你的部分**存进 `custom_system_prompt`，原样保留，永远在前面。
- **工具段**由 `SystemPromptBuilder.toolSection()` 生成，跟着 `ToolCatalog` 和三个开关（代码执行 / 本机命令 / 是否鸿蒙）走，永远追加在末尾。
- 你的部分为空时用默认开场白，输出与 1.11.0 之前**逐字节一致** —— 没自定义过的用户升级后看不出任何区别。

一段代码加一个工具，你写的那三行不用动，模型自动知道新指令。

### 编辑器也变了

提示词页现在只让你编辑自己那部分，下面多一块可折叠的只读预览：

```
你的部分
┌──────────────────────────┐
│ 回答用中文，代码注释也写中文。 │
│ 这是个 Kotlin + Compose 项目，│
│ 不要建议换框架。           │
└──────────────────────────┘
78 字符

▤ 自动追加的工具说明      查看
  6,842 字符 · 随工具表与开关更新
```

预览默认收起。展开后有好几千字，默认铺开的话，你自己写的那两行反而找不到了。

「恢复默认」改名叫「清空」—— 语义变了：清空之后不是回到出厂设置，而是只剩自动生成的工具段。

---

## 升级时你的旧提示词会怎样

旧版存的是整份文本，里面内嵌了工具段。直接拿来当「你的部分」会让工具说明出现两遍，所以首次读取时从 `## 指令格式` 处切开：

| 你当初做了什么 | 迁移结果 |
|---|---|
| 点过保存，但一个字没改 | 视为未自定义。切出来只有默认开场白，这种情况假装你自定义了没有意义 |
| 改了开场白，保留了工具段 | 只保留你改过的那截，工具段交给代码重新生成 |
| 整篇重写、压根没有工具段 | 整篇都算你的，后面再追加一份最新的工具段 |

旧 key `system_prompt` **不删除**。万一要回滚到 1.11.0，那时读的还是它。只有点「清空」会两个都删 —— 不然下次读取又会从旧 key 迁移回来。

---

## 已知限制

- 迁移靠 `## 指令格式` 这个标题定位。如果你当初的自定义里恰好也让 AI「输出一个叫 ## 指令格式 的标题」，会被误切。代码里用的是「标题 + 紧跟的那行说明」做匹配，误伤概率已经很低，但没有做到零。
- 工具段是纯文本拼接，不做去重。如果你在自定义里也手写了一遍指令说明，模型会看到两份 —— 内容一致倒不冲突，只是浪费 token。
- 提示词页的字符数是**拼接前**的：显示的是你写的那部分，不含自动追加的 6000+ 字。
