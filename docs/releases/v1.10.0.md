**多模型档案 + 思考过程 + 本机命令。** 之前只有一个模型、一种跑法，想换个后端就得手改配置。这一版把「配置」升级成「档案」，把「思考」显示出来，还让 AI 能在手机上直接跑命令。

## 🗂 模型档案：一套参数一份档案

地址、Key、模型名、是否支持看图、是否显示思考、上下文预算、温度 —— 这些原本是全局唯一的一份，现在收进 `ModelProfile`，想建几份建几份。

### 怎么切

**对话页点顶栏标题**，弹出列表直接选。选完立刻生效，不用重启、不用回设置页。

副标题会显示当前模型名，所以任何时候都能确认「我现在在跟谁说话」。

### 为什么值得做

三个几乎必然会撞上的场景：

- 写代码用 DeepSeek，看图得换 Qwen-VL —— 两边的 Base URL 和 Key 都不一样；
- 同一个服务商的推理模型（`deepseek-reasoner`）和普通模型，温度要求就不一样；
- 临时连一下本地 Ollama，切回来时不想把前面填的全 recall 一遍。

顺带解决了一个隐性 bug：上下文预算原本是全局值，但不同模型窗口从 8k 到 1M 不等，一个数字必然要么浪费要么溢出。

### 升级注意

旧的那份单份配置会在首次启动时**自动迁移**成名叫「默认」的档案，Key 不会丢。旧字段也没有删除 —— 万一要回滚到 1.9.0，填过的 Key 还在。

档案至少保留一份，删最后一份会被拦下来。

## 💭 思考过程：看得见它怎么想

推理模型（`deepseek-reasoner`、Kimi、QwQ 等）在正式回答前会吐一大段内心独白。之前这些内容被直接丢掉 —— 流式解析只取 `delta.content`。

现在三种字段名都认：`reasoning_content`（DeepSeek / Kimi / Qwen 系）、`reasoning`（OpenRouter）、`thinking`（部分自建网关）。

显示方式是**回答上方的折叠块**，不是塞进正文：

- 流式时自动展开，能看着它一个字一个字想；
- 结束后可以收起，标题上带字数；
- 展开限高 260dp，内部滚动 —— 一次思考两三千字很常见，不限高能把整个列表撑到要翻好几屏。

每个档案单独开关。普通模型没有这个字段，开了也是空的，不会报错。

### 一个必须说清的细节

**思考内容绝不回传。** 落盘是为了翻历史时能回看，但转成 API 消息时这个字段会被丢掉 —— 多数 OpenAI 兼容后端收到带 `reasoning_content` 的 assistant 消息会直接 400。

## 🖥 本机命令：`shell`

新增 `shell` 指令，在**你自己的手机上**执行命令，支持管道、重定向、`&&`：

```
shell grep -rn "TODO" . | head -20
shell ls -la && du -sh *
shell find . -name "*.kt" | wc -l
```

和 `run` 的分工：

| | `shell` | `run` |
|---|---|---|
| 在哪跑 | 你的手机 | Wandbox 远程容器 |
| 数据 | 不出设备 | 代码上传到 wandbox.org |
| 能看见工作区 | ✅ | ❌ |
| 语言环境 | 只有系统自带 toybox | Python / C++ / Rust / Go 等 30+ 种 |

**翻文件用 `shell`，跑代码用 `run`。**

### 工作区怎么进去的

这是最难的一处。工作区是 SAF 的 `content://` URI，**根本没有真实路径**，shell 进不去。

做法是镜像：执行前把工作区的文本文件拷到 `files/shell/work/`，执行完把新增和改过的文件写回工作区。所以：

```
shell echo "hello" > note.txt
```

执行完，`note.txt` 会真的出现在你的工作区里，用文件管理器能打开。

限制：单文件 512KB、总计 6MB、最多 300 个文件、最深 6 层。超出的不镜像 —— 一个二进制大文件就能把预算吃光。

**删除不同步。** `rm` 只删沙箱里的副本，真实文件还在。要真删请用 `delete` 指令（会弹确认框）。一次手滑不该是数据丢失。

### 什么命令会先问你

`rm -rf`、`mkfs`、`dd of=/dev/`、`reboot`、`pm uninstall`、`curl | sh`、往 `/system` 或 `/data` 写东西 —— 这些执行前弹确认框。

其余放行。理由：每条都弹的话，8 轮工具调用就是连点 8 次确认，用户最后只会在不看内容的情况下闭眼点「允许」，那比不拦更糟。

### 做不到的事

- **没有 python / node / gcc。** Android 系统只带 toybox（`ls` `cat` `grep` `sed` `awk` `find` `stat` `du` `ps` `date`）。
- **不能 `./脚本名`。** Android 10+ 的 W^X 策略禁止执行可写目录里的 ELF。要跑自己写的脚本用 `sh 脚本名`（执行的是系统的 sh，脚本只是参数）。
- **碰不到 `/sdcard` 和其它应用的数据。** 这是 SELinux，不是配置问题。
- **30 秒超时**，输出超 8000 字符保留头尾截断。`vim`、`top`、等输入的 `read` 会一直挂到超时，别用。

### 鸿蒙上直接没有这个功能

鸿蒙的沙箱规则和 Android 不完全一致，同一段命令可能直接抛 `IOException` 或者静默返回空。与其让人对着看不懂的报错反复试，不如在入口处砍掉：

- 设置页**整块不渲染**（不是灰掉，是不显示）；
- 模型收到的提示词是「本设备不支持」，不是「去设置里开一下」。

检测方式是**鸿蒙独有的痕迹**三路交叉：`hw_sc.build.os.version` 系统属性、版本字符串里的 `harmony` / `ohos`、`/system/bin/aa` 与 `bm` 同时存在。

刻意**没有**用 `Build.MANUFACTURER == "HUAWEI"` —— 那会把所有华为安卓机（EMUI）一起误杀，而那些设备的 shell 完全正常。

## ⚠️ 已知限制

- 思考过程是否真的出现，取决于后端有没有下发这个字段。OpenAI 的 o 系列走 chat completions 时**不下发** `reasoning_content`，界面上就是空的 —— 这是服务端的限制，不是解析漏了。
- `shell` 的镜像同步只处理文本文件。二进制（图片、压缩包）不会进沙箱，命令看不到它们。
- 镜像每次执行都是全量重拷（有大小上限）。工作区几千个文件时会明显变慢。
- 命令的输出上限 8000 字符，看长日志请用 `grep` / `head` 先筛。
- 切换档案不做二次确认，但**流式生成中禁止切换** —— 半个回答用 A 模型、半个用 B 模型毫无意义。
