# v1.11.2 — 连不上自己搭的后端时，至少要知道为什么

> 发布日期：2026-11-26 · versionCode 22 · 需要 Android 8.0（API 26）以上

## 一句话

修好了两个让「填对地址也连不上」的问题，并把网络报错从英文原文换成能照着操作的中文。

## 这一版解决什么

起因是一张截图：

```
Failed to connect to /127.0.0.1:8443
```

这句话技术上是准确的，但它没有回答任何一个实际问题：地址填错了？服务没启动？
协议不对？接下来该改哪一项？

顺着查下去，发现两处真缺陷。

### 1. 明文 HTTP 根本发不出去

`AndroidManifest.xml` 里写死了 `android:usesCleartextTraffic="false"`。
也就是说，只要你填的 Base URL 是 `http://` 开头，请求在建立连接前就被系统拦掉。

对一个「Base URL 随便填」的客户端来说这是硬伤 —— Ollama（11434）、llama.cpp（8080）、
one-api（3000）、LiteLLM（4000）、各种中转，默认全是明文。

现在改用 `res/xml/network_security_config.xml`，放开明文，但保留一条边界：

```
trust-anchors 只信系统证书，不信用户安装的 CA
```

否则任何装了抓包证书的设备都能解开 TLS 读到 API Key。

### 2. 报错是 OkHttp 原文，不是人话

`LlmClient.describe()` 原来只翻译了域名解析失败、超时、TLS 三类。
`ConnectException` 落到 `else` 分支，于是 `e.message` 被原样贴进气泡。

现在按主机类型分开说：

| 主机类型 | 提示内容 |
|---|---|
| `127.0.0.1` / `localhost` / `::1` | 点明它在手机上指手机自己，说明该填电脑的局域网 IP，附查 IP 的命令 |
| 局域网 IP（10/172.16-31/192.168/169.254/100.64） | 三件事逐一确认：服务起了没、监听的是不是 `0.0.0.0`、防火墙放行没 |
| 公网地址 | 地址与网络的基本检查 |

TLS 失败也分了两种情况：往明文端口发 https（提示改 `http://`）、自签名证书不被系统信任。

## 界面变化

Base URL 输入框下方现在会实时提示，三种情况可叠加：

```
Base URL
┌────────────────────────────────────┐
│ http://127.0.0.1:8443              │
└────────────────────────────────────┘
这个地址指向手机自己。服务跑在电脑上要填电脑的
局域网 IP（如 192.168.1.5），不是 127.0.0.1。
```

另一种：

```
│ http://example.com:3000            │
公网地址用了 http：API Key 和对话内容会明文经过
网络。能用，但建议改成 https://。
```

局域网地址则用中性色提示「记得让服务监听 0.0.0.0」。

## 补全规则变了

不带协议头时，按主机类型补：

| 输入 | 补成 | 原因 |
|---|---|---|
| `192.168.1.5:8080` | `http://192.168.1.5:8080` | 局域网自建服务几乎都是明文 |
| `api.deepseek.com` | `https://api.deepseek.com` | 公网服务几乎都是 https |

原来一律补 `https://`。局域网地址被送到 TLS 握手会报「握手失败」，
用户看着这句去查证书，而真正的问题是他连协议都没写。

## 怎么连电脑上的服务

1. 电脑上查局域网 IP：Windows `ipconfig`、macOS/Linux `ifconfig` 或 `ip addr`，
   找形如 `192.168.x.x` 的那一行。
2. 确认服务监听 `0.0.0.0` 而不是 `127.0.0.1`。以 Ollama 为例：
   `OLLAMA_HOST=0.0.0.0:11434 ollama serve`
3. 放行防火墙端口（Windows 首次监听会弹窗，选「专用网络」）。
4. 手机和电脑连同一个 Wi-Fi。
5. 手机浏览器先访问 `http://192.168.x.x:端口`，能出东西再回来填进 App。

**`127.0.0.1` 和 `localhost` 在手机上永远指手机自己** —— 这不是本应用的限制，
是所有联网程序都一样的语义。

## 已知限制

- debug 签名，多个设备安装时包名相同会互相覆盖。
- 明文 HTTP 现在全局放开，公网 `http://` 的地址只警告不禁止 —— 判断权在用户。
- 自签名证书的 https 后端仍然连不上（系统不信任），只能改用 http 或换正式证书。
