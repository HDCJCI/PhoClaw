# PhoClaw

一个可在手机上运行、能对话并直接读写工作区文件的 Android 应用。（仅无聊开发的软件）

**当前版本：v1.6.4**（versionCode 11）

**中文** · [English](README.en.md)

> 它**不包含任何硬件连接、蓝牙/WiFi 配网、元件控制功能**——只有两件事：
> **写代码** 和 **聊天**。

---

## 它是什么

一个完整的 Kotlin + Jetpack Compose Android 工程。装上之后：

1. 填入你自己的 API Key（DeepSeek / OpenAI / 通义 / 任何 OpenAI 兼容接口）
2. 从系统目录选择器里选一个文件夹作为**工作区**
3. 开始聊天——AI 可以**真正读写你选的这个文件夹**里的文件

AI 通过一种约定的代码块格式操作文件：

````
```phoclaw:tree .
```

```phoclaw:read src/main.js
```

```phoclaw:write src/main.js
console.log("hello");
```

```phoclaw:copy src/a.js -> src/b.js
```
````

应用会解析这些指令、在真实文件系统上执行、把执行结果回灌给模型，模型据此继续下一步（最多 8 轮，避免死循环）。

> 旧前缀 `espclaw:` 仍然兼容，历史对话里的格式不会失效。

## 支持的指令

| 指令 | 用途 |
|---|---|
| `list <目录>` | 列出目录下的文件和子目录 |
| `tree <目录>` | 递归展示目录树（默认 3 层，最多 300 条） |
| `read <文件>` | 读取文件全文（超 512KB 会拒绝，避免撑爆上下文） |
| `write <文件>` | 写入文件，覆盖原有内容，父目录自动创建 |
| `append <文件>` | 在文件末尾追加内容 |
| `search <关键词> [目录]` | 搜索**工作区文件内容**，返回「文件:行号: 内容」 |
| `websearch <关键词>` | **联网搜索**互联网，返回摘要与带来源链接的片段 |
| `info <路径>` | 查看大小、类型、修改时间 |
| `mkdir <目录>` | 创建目录 |
| `copy <源> -> <目标>` | 复制文件或目录（目录递归复制） |
| `move <源> -> <目标>` | 移动或重命名 |
| `delete <路径>` | 删除文件或目录 |

**别名**：`ls`=`list`、`cp`=`copy`、`mv`=`move`、`rm`/`del`=`delete`、`md`=`mkdir`、`grep`/`find`=`search`、`stat`=`info`。
`websearch` 也接受 `web_search` / `wsearch` / `webs` / `netsearch`。
`copy` / `move` 的参数也支持空格分隔：`cp a.js b.js`。

> ⚠️ `search` 和 `websearch` **不是一回事**：前者搜你工作区里的文件内容，后者搜互联网。
> 技能白名单里写 `search` 只放开本地文件搜索，**不会**让 AI 能上网。

### 危险操作需要你确认

`delete` 和 `move` 属于不可逆操作，**在聊天里**执行前会弹出确认框，你点「允许」才会执行，
点「拒绝」则跳过并把结果告诉模型。模型无法绕过这一步。

**在自动化任务里**（后台无人值守，没有对话框可点）改由任务级的
「允许危险操作」开关决定：不开就一律拒绝并把「已拒绝」写回日志，模型因此知道
发生了什么、可以换个方式继续，而不是傻等一个永远不会有人点的确认框。

### 安全护栏

- 单文件读取上限 **512 KB**，搜索时跳过二进制文件和超过 1 MB 的文件
- 目录树最多递归 3 层、300 条，防止超大仓库撑爆上下文
- 禁止 `..` 路径穿越；禁止把目录复制/移动进它自己的子目录（否则会无限递归）
- 任何含 `..` 的路径会被直接拒绝

### Markdown 渲染了什么

| 语法 | 效果 |
|---|---|
| `# 标题` ~ `##### 标题` | 五级标题，字号与字重递增 |
| `**粗体**` / `*斜体*` / `~~删除~~` | 行内样式 |
| `` `行内代码` `` | 等宽字体 + 浅色底 + 圆角 |
| ` ```lang ` 代码块 | 等宽字体、深色底、边框、左上角语言标签，**可横向滚动** |
| `- 项` / `1. 项` | 无序/有序列表，有序列表自动编号 |
| `> 引用` | 左侧竖线 + 斜体 |
| `\| 表 \| 表 \|` | 表格，列宽按内容自适应，整体**可横向滚动** |
| `---` | 分割线 |
| `[文字](url)` | 带下划线的强调色文字 |

> **流式期间不渲染 Markdown**：AI 正在输出时按纯文本显示，整段回复结束后再一次性渲染。
> 否则未闭合的 ` ``` ` 会让排版在中途反复跳动。

## 技能（Skills）

技能 = **提示词** + **指令白名单**。从「技能」页导入本地文件即可，支持两种格式。

### 格式一：Markdown + frontmatter（推荐）

```markdown
---
name: 代码审查
description: 按团队规范审查代码
actions: read, list, tree, search
---

你是一名严格的代码审查员。审查时重点关注：
1. 空指针与数组越界
2. 未处理的异常
3. 命名是否符合团队规范
```

`actions` 省略 = 不限制指令。**写错的动作名会直接报错**，不会静默忽略 ——
静默丢弃会让白名单变得比你以为的更严（或更松），两种情况都会让人误判安全性。

### 格式二：纯 JSON

```json
{
  "name": "代码审查",
  "description": "按团队规范审查代码",
  "allowedActions": ["read", "list", "tree", "search"],
  "prompt": "你是一名严格的代码审查员……"
}
```

没有 frontmatter 的 `.md` 也能导入：文件名当名称，全文当提示词，不限制指令。

### 白名单是怎么生效的

- 技能**激活后**，提示词被拼进 system message，指令白名单在每次执行前逐条过滤
- 多个技能都声明白名单时取**并集**（你能用「这些」），全都没声明则不限制
- 被拦下的指令**会把「已拒绝」写回日志**给模型看。不能静默丢弃 ——
  否则模型收不到任何反馈，会反复重试同一条指令直到 8 轮用尽
- 白名单是**能力收窄**：技能无法给模型超出原有 11 条指令的权限。
  即使导入来路不明的技能，最大风险也只是模型被误导，不会凭空获得删除能力

> 没激活任何技能时，系统提示词与你设置里写的一字不差 —— 行为完全不变。

## 联网搜索

AI 的**知识有截止日期**。问它「今天有什么新闻」「DeepSeek 最新版本是多少」，
它只能凭记忆猜——猜错了还说得理直气壮。联网搜索就是解决这个的。

### 怎么开启

1. 去 [app.tavily.com](https://app.tavily.com) 注册，拿一个免费 Key（形如 `tvly-xxxxx`）
2. 在 PhoClaw **「设置」→「联网搜索」** 里粘贴，点「保存搜索设置」
3. 点「测试搜索」验证能不能通

> 设置页里的「去 Tavily 申请免费 Key」会用**系统浏览器**打开，不是内嵌 WebView ——
> 那需要额外维护一套页面，也会让你在应用内输入第三方账号密码，反而更不安全。

### 它是什么形态：一条新指令，而不是自动搜索

`websearch` 和 `read` / `write` 一样是**模型自主决定何时调用**的指令。AI 判断问题涉及
实时信息时才会搜；普通对话、写代码、数学计算这些稳定知识它直接回答。

**为什么不每条消息都自动搜一遍**：

| | 自动搜索 | 按需调用（本方案） |
|---|---|---|
| 延迟 | 每条消息都要等一次搜索往返 | 只有需要时才等 |
| 成本 | 每句话都烧一次搜索配额 | 只在真正需要时烧 |
| 效果 | 搜出来的东西未必相关，反而**干扰**模型 | 由模型判断该搜什么关键词 |

### 搜索返回什么

Tavily 是专为 LLM 设计的搜索接口，返回的是**已经抽取好的正文片段**（不是 HTML），
所以不需要我们再解析网页。格式如下：

```
===== 联网搜索结果：2026年最新 Kotlin 版本 =====

【摘要】
Kotlin 2.2.0 是当前最新稳定版本……

[1] Kotlin Releases
来源：https://kotlinlang.org/docs/releases.html
Kotlin 2.2.0 released……

[2] ……
===== 搜索结果结束 =====
```

**刻意带上 URL**：模型可以在回答里引用来源，你也能自己核对。
模型整合出来的摘要未必可靠 —— 给了链接你才有验证的余地。

### 上下文占用控制

| 项 | 值 | 原因 |
|---|---|---|
| 返回条数 | 默认 5（可调至 20） | 再多对模型帮助有限，却显著挤占上下文预算 |
| 单条正文 | 截断到 1200 字符 | Tavily 的 `content` 有时是整篇文章，5 条各 5000 字一下吃掉大半上下文 |
| 读超时 | 45 秒 | 搜索是同步一次性请求（不是流式），但 advanced 深度 + 慢站点时给短了会误杀 |

### 没配 Key 会怎样

**不会静默失败。** 三条不同的回灌文本，让模型知道该怎么做：

| 情形 | 回灌给模型的内容 |
|---|---|
| Key 为空 | 「联网搜索未启用……请直接告知用户需要配置该 Key，**并改用你已有的知识回答，不要重复尝试搜索**」 |
| 搜索失败 | 「联网搜索失败：<原因>。你可以换一个更具体的关键词**重试一次**，或直接根据已有知识回答」 |

> 第二句里的「重试一次」是刻意的 —— 不说明次数的话，模型会反复重试同一条指令直到 8 轮用尽。
> 这跟技能白名单拦截时回灌「已拒绝」是同一个道理：**拦截必须让模型知道**。

HTTP 错误也分情形给了可行动的说明：401/403 是 Key 错或过期、429 是频率或配额、
432/433 是用量限制、5xx 是服务端问题。

### 聊天和定时任务都能用

`CommandDispatcher` 是前台对话与后台 `HeadlessTurnRunner` **共用**的同一份实现。
定时任务里的 AI 同样能联网 —— 比如「每天早上 9 点搜一下今天的科技新闻并总结」。

> 执行器每次构造时**实时读**当前 Key，而不是缓存住。否则你在设置里改了 Key，
> 得重启应用才生效。

### 安全

- **API Key 加密存储**，与 LLM 的 Key 一样走 `EncryptedSharedPreferences` + Keystore
- 联网搜索**只有读取能力**，不会把工作区文件传出去 —— 发出去的只有模型自己写的那几个关键词
- 技能白名单里 `websearch` **独立于** `search`。不想让某个技能联网，白名单里不写它就够了

## 自动化定时任务

在「自动化」页新建任务，填四项：

| 字段 | 说明 |
|---|---|
| 标题 | 列表上显示的名字，也是执行记录会话的标题 |
| 简介 | 一句话说明（可选） |
| 任务描述 | 自然语言，到点原样作为消息发给 AI |
| cron 表达式 | 5 段或 6 段，自动识别 |

到点后 PhoClaw 会在**后台无人值守**地跑完整轮对话（提问 → 调用工具 → 回灌 → 继续，
最多 8 轮），完成后发通知；点通知直接跳到该任务的执行记录。

### cron 支持范围

```
5 段：  分 时 日 月 周        例如  0 9 * * 1-5     工作日 9:00
6 段：  秒 分 时 日 月 周     例如  0 */5 * * * *   每 5 分钟
```

每个字段支持 `*`、`a-b`、`a,b,c`、`*` `/n` 步长、`a/n`，月份与星期可用 `JAN`/`MON` 这类英文缩写。

**不支持** Quartz 专有的 `?` `L` `W` `#`。它们会**明确报错**而不是被忽略 ——
静默接受一个自己实现不了的语义，会让你以为任务已生效、实际却永远不触发。
`?` 是唯一的例外：它语义上就等于 `*`，所以当作 `*` 处理，但界面会提示。

> **日与周同时指定时是 OR**（Vixie cron 标准语义）。
> `0 0 1 * 1` 表示「每月 1 号 **或** 每周一」，不是两者都要满足。这是最容易搞错的一处。

编辑页会**实时算出未来三次触发时刻**并显示。cron 很抽象，写错了一看一眼就知道。

### 危险操作的处理

后台执行时没有人能点确认框，所以 `delete` / `move` 由任务级的
**「允许危险操作」开关**决定。默认关闭：

- **关闭时**：AI 收到「该操作在自动任务中被禁止」的说明，可以换个方式继续，
  而不是傻等一个永远不会有人点的对话框
- **开启时**：直接执行。勾选这个开关**就是一次预先授权** ——
  等价于「在这个任务的范围内永久批准删除/移动」，所以界面上给了红色警告

### 调度与权限

| 事项 | 说明 |
|---|---|
| 触发方式 | `AlarmManager.setExactAndAllowWhileIdle`，Doze 模式下也能准时唤醒 |
| 精确闹钟权限 | 同时声明 `USE_EXACT_ALARM`（Android 13+ 自动授予）与 `SCHEDULE_EXACT_ALARM`（12+ 需手动授权） |
| 拒绝授权怎么办 | **自动降级**为不精确闹钟，任务照跑，最差晚十几分钟；界面显示「非精确模式」角标。功能不会直接不可用 |
| 通知权限 | Android 13+ 在首次新建任务时申请；拒绝了任务照跑，只是结果通知不到 |
| 重启后 | `BootReceiver` 在开机 / 改时间 / 改时区 / 应用升级后重建全部闹钟 |
| 被「强行停止」后 | 强行停止的应用收不到任何广播。PhoClaw 在**每次冷启动**时补一次校准，这是唯一能恢复的时机 |

> ⚠️ 部分国产 ROM 会激进地清理后台。如果任务不触发，请在系统设置里把 PhoClaw
> 加入电池优化白名单。应用内不做自动跳转引导 —— 那会被应用商店判定为诱导行为。

### 为什么用前台服务而不是 WorkManager

WorkManager 的周期任务最小间隔 15 分钟，且 Doze 下会被批量延迟。用户的诉求是「尽量准时」，
所以用 AlarmManager 精确闹钟。

而 `BroadcastReceiver.onReceive` 只有约 10 秒窗口，一轮任务最多 8 次工具调用，
轻松超过 30 秒 —— 超时会被系统直接强杀并记为 ANR。所以用前台服务承载执行，
代价是必须挂一个不可划掉的常驻通知。

### 执行记录

每个任务**固定绑定一个会话并覆盖写**，而不是每次执行新建会话。
一个每小时跑的任务一天会产生 24 个会话，把历史页彻底淹没，你就找不到自己真正聊过的东西了。

## 附件

输入框左边的 **「+」** 按钮选图片或代码/文本文件，可以多选、可以只发附件不打字。

### 图片和文本走两条完全不同的路

| | 图片 | 代码 / 文本文件 |
|---|---|---|
| 发送方式 | 转 Base64，走多模态 `image_url` | 内容全文内联进上下文 |
| 是否常驻 | **否**，只发当前轮 | **是**，后续每轮都带上 |
| 为什么 | 图片体积大，每轮重发会让请求体迅速膨胀 | 你希望 AI 在多轮里反复引用这份代码 |

历史消息里的图片不会重新发送，只留一个 `[图片 xxx.png]` 占位保留位置感。

### ⚠️「模型支持看图」开关

**在设置页，默认关闭。** 这个默认值是刻意的保守选择。

多模态协议要求把消息的 `content` 填成数组格式，而不支持视觉的后端（老版 Ollama、部分国产网关）收到数组会**直接返回 400**。所以：

| 开关 | 行为 |
|---|---|
| **关闭**（默认） | 图片只发文字说明。模型知道「用户发了张图」但看不到画面。**任何后端都不会因此报错** |
| **开启** | 图片以 Base64 通过 `image_url` 传给模型，模型真正能「看见」 |

用 `gpt-4o`、`qwen-vl-max`、`glm-4v` 这类支持视觉的模型时打开它；用 `deepseek-chat` 这类纯文本模型时保持关闭。

### 图片会被压缩

| 参数 | 值 | 说明 |
|---|---|---|
| 长边上限 | 1568 px | 主流视觉模型的实际处理分辨率上限，传更大纯属浪费带宽和 token |
| 压缩质量 | JPEG 85 | 代码截图文字仍然清晰 |
| 触发阈值 | 大于 1 MB 或长边超限 | 更小的图不重编码，因为重编码小图往往反而变大 |

压缩后会提示「已压缩 4.8MB → 420KB」。

> 压缩算法全程遵循「先读边界 → 采样解码 → 精确缩放」，
> **绝不对原图做整图解码** —— 一张 8000×6000 的图整解要 190MB 内存，直接 OOM。

### 大小限制

| 项 | 上限 |
|---|---|
| 单张图片（原始） | 12 MB |
| 单个文本文件 | 256 KB |
| 单轮内联文本总量 | 200 KB（超出会截断并明确标注） |
| 单次发送附件数 | 6 个 |
| `files/attachments/` 总量 | 200 MB 软上限，超出后从最旧的开始清理到 150 MB |

### 文件存在哪

复制到应用私有目录 `files/attachments/`，文件名是随机 16 位十六进制串（不掺原文件名，避免中文、表情、超长名、路径分隔符的麻烦）。会话 JSON 里只存引用，**不存 Base64** —— 否则一张几 MB 的图会让每次读写聊天记录都卡顿。

清理时机：

- 删会话 → 该会话引用过的附件一并删除
- 清空历史 → 整个附件目录清空
- 冷启动 / 退到后台 → 扫描一次孤儿文件（跳过 5 分钟内修改过的，避免误删正在发送的）

> 附件被清理后，历史消息里会显示「图片已不可用」占位，**不会崩**。

### 选不到某些代码文件？

选择器已经放开了任意文件类型（因为 `.kt` / `.py` / `.gradle` 这类文件系统常常认不出 MIME，收紧的话它们会是灰的）。真正的内容过滤在读取层：**含 NUL 字节的文件会被判定为二进制并拒绝**，不会把压缩包当文本塞给模型。

## 对话存储

对话**自动保存**，不需要手动点保存。重开应用会直接接着上次的聊。

### 存在哪

存在应用私有目录 `files/conversations/`，每个会话一个 JSON 文件：

```
files/conversations/
├── index.json          索引：只放 id / 标题 / 时间 / 消息数
├── a1b2c3d4e5f6.json   一个会话的全部消息
└── ...
```

- **列表页只读 `index.json`**，不用把每个会话的正文全解析一遍
- **写入用「临时文件 + 原子替换」**：先写 `.json.tmp` 再 rename。写到一半被系统杀进程时，最多丢这一次更新，不会留下半个损坏的会话文件
- 放在应用私有目录里，其他应用和文件管理器看不到，卸载应用时一并清除

### 什么时候写

| 时机 | 行为 |
|---|---|
| 一轮对话结束 | 立即落盘（此时消息完整） |
| 请求出错 | 立即落盘（已经问了一半，重开也该看得见） |
| 用户点停止 | 立即落盘，保留已生成的内容 |
| 切到新会话 / 打开历史会话 | 先把当前会话存了再切 |
| 应用退到后台 | 强制落盘 |
| 流式生成过程中 | **防抖 1.2 秒**：逐字增量每几十毫秒来一次，等安静下来再写 |

> **流式中的半截内容不落盘**，避免存下写了一半的回复。

### 会话标题怎么来的

取**首条用户消息**的首行，压掉多余空白，截断到 24 个字符。超出部分用 `…` 收尾。

没有调用模型来总结标题——那会给每句话都多加一次 API 请求和等待，本地截断够用了。

### 历史页

聊天页顶栏最左边的时钟图标进入。列表按更新时间倒序，显示「标题 + 时间 + 消息数」，时间会渲染成「今天 14:30 / 昨天 09:12 / 3天前 / 3月5日」这种人话。

- 点条目 → 载入该会话继续聊
- 点右侧垃圾桶 → 二次确认后删除
- 顶栏溢出菜单 → 清空全部历史（同样二次确认）

> 删除会话**不影响工作区文件**，删的只是聊天记录。

## 配置 API

在「设置」页填入三项：

| 项 | 说明 | 示例 |
|---|---|---|
| API Key | 你的密钥 | `sk-xxxxxx` |
| Base URL | **只填到域名**，不要带接口路径 | `https://api.deepseek.com` |
| 模型名 | 服务商提供的模型标识 | `deepseek-chat` |

想用联网搜索的话，再多填一项 **Tavily API Key**（见上文「联网搜索」章节）。留空不影响其他功能。

### ⚠️ Base URL 最常见的错误

**不要**把文档里的完整接口地址粘进来：

| | 写法 |
|---|---|
| ✅ 正确 | `https://api.deepseek.com` |
| ❌ 错误 | `https://api.deepseek.com/v1/chat/completions` |
| ❌ 错误 | `https://api.deepseek.com/v1` |

程序会在你输入时**实时红字提示**，并在保存时**自动剥离**多余的路径段。
所以你即使粘错了也能跑，但建议直接按正确格式填。

### 各服务商对照

| 服务 | Base URL | 模型名示例 |
|---|---|---|
| DeepSeek（默认） | `https://api.deepseek.com` | `deepseek-chat` |
| OpenAI | `https://api.openai.com` | `gpt-4o-mini` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode` | `qwen-plus` |
| Moonshot | `https://api.moonshot.cn` | `moonshot-v1-8k` |

用本机 Ollama 的话，改 Base URL 为 `http://<你的IP>:11434`，并在 `AndroidManifest.xml` 里把
`android:usesCleartextTraffic` 改成 `true`（http 明文需要，公网服务务必保持 `false`）。

### 对话循环是怎么跑的

```
用户输入
  ↓
streamingCompletion()  →  SSE 逐字上屏，就地创建/更新同一条助手气泡
  ↓
CommandParser.parse()  →  切出指令块，界面只显示摘要
  ↓
finalizeAssistant()    →  复用该气泡，替换为去掉指令块后的正文
  ↓
executeCommands()      →  delete/move 先弹确认框，其余直接执行
  ↓
日志作为 internal 消息回灌 →  回到 streamingCompletion()
  ↓
模型不再输出指令 → 结束（最多 8 轮）
```

`streamingCompletion()` 返回的是 `(文本, 消息下标)`，`finalizeAssistant()` 直接复用该下标 ——
这样回复**不会出现重复气泡**。

## 安全说明

- **工作区即权限边界**。应用只能访问你用系统选择器明确授权的那个目录。
- **路径穿越防护**。`WorkspaceRepository.sanitize()` 会拒绝任何含 `..` 的路径。
- **凭据加密**。API Key 经 Keystore 加密落盘，`allowBackup=false` 防止被系统备份拖走。
- **对话明文存储**。对话记录存在应用私有目录，**未加密**——它不像 API Key 那样敏感，
  加密反而会让用户无法自行导出。但请留意：聊过的内容会一直留在手机上，直到你手动删除。
- **AI 有写权限，请注意**。模型可以覆盖工作区内的文件，重要数据别放进工作区。
